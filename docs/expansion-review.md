# 확장 수정사항 및 추가 코드 검토

검토일: 2026-09-18

검토 대상은 `수정사항.txt`와 `gemini-code-1789691135283.js`이다. 아래 문제 목록은 첨부 코드 원본의 정적 검토 기록이다. 이후 사용자의 적용 요청에 따라 현재 모듈 구조에 맞춰 통합했으며, 실제 규칙과 검증 경로는 [확장 QA 매뉴얼](expansion-qa.md)에 정리했다.

## 현재 작업과의 관계

기존에 요청한 작업은 현재 분리된 React/Vite 구조에서 구현했다.

- 화면 폭과 높이에 따른 장면/선택지 재배치와 보조 패널 접기.
- `scene_000_op.webp` 인트로와 게임 시작/설정/도움말 메뉴.
- 헤더 설정/도움말 모달, 글씨 확대와 번쩍임 제거 설정 저장.
- ZIP 다운로드 UI와 구현 제거.
- 크기를 고정한 주사위 모달과 투명 주사위 이미지, 캔버스 효과.
- 이야기/엔딩의 텍스트 출력 효과와 즉시 완성 버튼.
- 전체 폭을 사용하는 엔딩 카드 화면과 크레딧.

추가 코드는 데이터, 오디오, reducer, UI가 하나로 합쳐진 별도 앱이다. 상태명은 `phase`, `character`, `shaftPhase`이며, 현재 앱의 `stage`, `player`, `flags`와 다르다. 아이템 ID도 대문자로 변경되어 직접 붙여넣으면 기존 핸들러와 저장/표시 규약이 맞지 않는다.

## 문서가 제안하는 확장

| 항목 | 통합 전 앱 | 첨부 자료 |
| --- | --- | --- |
| 탐사 선택지 | Stage 1은 6개, Stage 2~4는 4개 | Stage 1~4 각각 6개, AP 3 |
| 정신력 | 기본 SAN 30, 컨디션에 따라 최대치 조정 | 최대 SAN 15 |
| 최종전 | 배기팬 정지 후 맨홀 개방 | 배기팬 → 촉수 견제 → 맨홀, 3단계 |
| 엔딩 | 5종 | GOOD 추가, 6종 |
| 캐릭터 선택 | 즉시 확정 | 프리뷰 후 탑승 확정 |
| 주사위 | 이미지 회전 + 캔버스 | 이미지를 없애고 숫자 셔플 |
| 수집 | 미구현 | 엔딩 도감 + 전체 수집 히든 후일담 |

숫자 주사위로 전면 교체하는 안은 최근 요청한 투명 주사위 에셋/캔버스 연출과 다르다. SAN과 엔딩 조건 변경도 게임 규칙을 바꾸므로 UI 개선과 구분해 통합해야 한다.

## 우선 수정해야 할 추가 코드 문제

1. **0턴 행동이 1턴을 소모한다.** 455행의 `action.payload.turnCost || 1`은 `0`을 `1`로 바꾼다. 2단계 랜턴과 소화기에서 넘긴 `turnCost: 0`이 무시된다. 기본값은 `?? 1`로 처리해야 한다.
2. **도구를 갖고 있지 않아도 도구 특전이 성공한다.** 593행 이후 Phase 1 TOOL, Phase 2 LANTERN/EXTINGUISHER/CUTTER는 소지 여부를 확인하지 않는다. 해당 버튼도 항상 표시된다. UI와 핸들러 양쪽에 보유 도구 검증이 필요하다.
3. **최종전 턴 소진을 즉시 판정하지 않는다.** Phase 1 실패나 Phase 2 행동으로 턴이 0이 되어도 다음 행동이 가능하다. BAD 3은 맨홀 주사위 실패 분기에서만 검사한다. 턴 경계와 마지막 턴의 탈출 성공 우선순위를 공통 처리해야 한다.
4. **HP/SAN 0에서도 계속 진행하거나 탈출 엔딩을 얻을 수 있다.** 피해 reducer는 0으로 제한하지만 사망/붕괴 판정이 없다. GOOD 조건은 HP와 SAN을 모두 확인해야 하며, 생존 판정을 먼저 해야 한다.
5. **소지품 5칸이 가득 차면 보상이 조용히 사라진다.** 363~368행은 아이템을 추가하지 않고도 획득 플래그를 켠다. 랜턴이 실제 소지품에 없는데 배터리 면제가 활성화되는 등 불일치가 생긴다. 슬롯 제한을 유지하려면 교체/버리기와 명확한 안내가 필요하다.
6. **컨디션 보정으로 HP가 최대치를 넘는다.** 325행은 HP 상한을 제한하지 않아 22/20이 될 수 있다. SAN 20 보정 +5는 이미 15인 SAN에 상한이 걸려 실제 증가가 없으며, 조건 텍스트의 공포 면역을 구현하는 별도 로직도 없다.
7. **문서에 적힌 도구 연계가 일부 미구현이다.** 절연장갑, 산성점액병의 효과와 CCTV `knowsBreaker` 보너스는 데이터에만 존재한다. Phase 1의 도구 정공법은 스패너/멀티툴/점액을 구별하지 않는다.
8. **이미지 경로와 화면 연동이 현재 에셋과 다르다.** 기존 캐릭터/아이템 경로는 `.png`지만 실제 파일은 `.webp`다. 추가 코드의 엔딩/도감은 카드 이미지를 출력하지 않고, 펌프실/약국 배경과 히든 보고서 배너도 연결하지 않는다. 문서의 배너 코드는 JS 파일에 반영되지 않았다.
9. **모바일 레이아웃 개선이 충분하지 않다.** 고정 12열에 좌/중/우를 3/6/3으로 유지하고, 16:9와 최소 높이 640px을 강제한다. 좁은 화면에서 중앙 선택지 폭이 크게 줄어 현재 겪었던 문제를 다시 만든다. HUD AP 글자는 모바일에서 숨겨진다.
10. **저장값과 연속 입력 보호가 부족하다.** 엔딩 저장값은 JSON 파싱 후 배열인지 검증하지 않아 유효한 JSON 객체로 저장되면 `.includes`가 실패할 수 있다. 컨디션 버튼 연속 클릭, 결과 확정 중복 클릭, 타이머/인터벌 정리도 보강해야 한다.

추가 reducer의 `USE_ITEM` 역시 소지 여부를 확인하지 않고 ID만으로 회복한다. 현재 UI에서는 소지 슬롯을 통해 호출하지만, 규칙 무결성을 위해 reducer 자체에서도 검증해야 한다.

## 최종 통합 결정

현재 `stage/player/flags` 상태와 아이템 ID를 유지하고, 탐사 데이터와 공통 규칙을 별도 모듈로 옮겼다. 캐릭터 프리뷰, 6종 카드/도감, 전체 수집 후일담을 연결했다.

- GOOD은 `HP >= 10 && SAN >= 7`, TRUE는 `HP >= 12 && SAN >= 8`이다. 생존 판정을 먼저 한다.
- 기존 앱처럼 소지품을 모두 보관한다. 5칸 제한으로 보상을 삭제하지 않는다. 같은 ID의 도구는 중복 추가하지 않는다.
- 기존 이미지 주사위/투명 회전 에셋/캔버스/고정 모달 높이를 유지한다.
- 0턴 행동, 마지막 턴 성공 우선 처리, 모든 단계의 턴 소진과 HP/SAN 붕괴를 처리한다.
- 절연장갑의 감전/산성액 보호와 CCTV 보너스, 산성액 소모, 소지품 회복 버튼을 구현한다.
- 프리뷰와 도감 모달은 바깥 클릭/Esc로 닫히며 키보드 포커스를 유지한다.
- 저장값에서 알려진 엔딩 ID만 읽고, 중복이나 JSON 객체 등 잘못된 형식은 무시한다.
