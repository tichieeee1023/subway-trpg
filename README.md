## 프로젝트 개요

| | |
| --- | --- |
| 장르 | 브라우저에서 바로 플레이하는 한국어 텍스트 호러 TRPG |
| 배경 | 비 내리는 새벽, 서울 지하철 2호선 신도림역 막차 6호차 |
| 플레이 | 5개 캐릭터 아키타입 · D20 판정 · 구역별 제한 조사 |
| 목표 | 단서와 도구를 활용해 환기탑을 돌파하고 지상으로 탈출 |
| 엔딩 | BAD 3종 · NORMAL · GOOD · TRUE, 총 6개 수집형 결말 |

각 구역에서 여섯 장소 중 세 곳만 조사할 수 있습니다. 어떤 위험을 감수하고 어떤 도구를 확보했는지가 최종 탈출의 선택지를 바꿉니다.

## 게임 흐름

```text
2장면 프롤로그 → 캐릭터 선택 · 컨디션 D20
       ↓
암전된 6호차 → 선로 터널 → 환승역 플랫폼 → 지하 상가
       ↓
환기탑 갱도 최종전 → 엔딩 카드 · 도감 · 히든 후일담
```

처음 프롤로그를 본 뒤에는 같은 브라우저에서 자동으로 생략할 수 있고, 인트로에서 직접 건너뛸 수도 있습니다.

## 플레이 시스템

### 캐릭터와 판정

다섯 아키타입 중 하나를 선택하고 D20으로 당일 컨디션을 정합니다. 능력치와 특성이 판정에 반영됩니다.

```text
판정값 = D20 + 능력치 보정 + 특성 보정
```

Natural 20은 대성공, Natural 1은 대실패입니다. HP 또는 SAN이 0이 되면 생존에 실패합니다.

### 제한 조사와 도구

- Stage 1~4에서 구역별 6개 장소 중 최대 3곳을 조사합니다.
- 조사 전에는 현장 단서만 제공하고, 보상과 위험은 선택 후 공개합니다.
- 도구·단서·회복 아이템과 조사 기록은 이후 경로와 최종전 선택지에 영향을 줍니다.
- 헤더의 전구 버튼은 정답을 직접 말하지 않는 한 줄 생존 힌트를 제공합니다.

### 엔딩 도감

BAD 3종, NORMAL, GOOD, TRUE의 6개 엔딩을 수집합니다. 첫 엔딩을 보기 전에는 도감이 잠겨 있으며, 완료한 카드만 브라우저 `localStorage`에 저장됩니다. 6개를 모으면 **04:44 AM — 폐쇄회로 밖의 기록** 후일담이 열립니다.

개발 모드에서는 메인 화면에서 `Ctrl + Shift + F10`으로 도감 전체 해금이 가능합니다. 엔딩 조건과 스포일러를 포함한 검증 기준은 [QA 매뉴얼](docs/expansion-qa.md)을 참고하세요.

## 반응형·접근성

PC는 캐릭터 시트·장면·시스템 로그의 3열 구성입니다. 장면 이미지는 먼저 크게 보이고, 설명은 아래에서 따로 펼칠 수 있습니다. 좁은 화면에서는 캐릭터 시트와 로그를 접을 수 있는 패널로 재배치하고, 선택지의 터치 영역과 제목 줄바꿈을 조정합니다.

설정은 브라우저에 자동 저장됩니다.

- 글씨 크기: 기본 / 크게
- 번쩍이는 이펙트 제거: 플래시, 암전, 캔버스 효과 등 감소
- 주사위 연출 생략: 다회차에서 결과 즉시 표시
- `prefers-reduced-motion` 환경에서 타이핑과 애니메이션 감소

플레이 도중 설정에서 `처음부터 다시 플레이`를 고르면 확인 후 현재 회차만 초기화하며, 엔딩 도감은 유지됩니다. `홈으로 가기`는 탭에 남은 회차를 보존하고 메인 버튼을 `이어하기`로 바꿉니다. 이어하기 상태는 새로고침 후 복원되는 저장 슬롯은 아닙니다.


## 최근 개발 기록 · 2026-09-18–19

최근 작업은 모바일에서의 가독성과 엔딩 완주 경험을 중심으로, 게임의 시각·음향 연출 및 두 작품을 잇는 메인 화면까지 정리했습니다.

### 장면·반응형 레이아웃

- 모바일에서 제목이 `냉동 / 고 탈출`처럼 어절 중간에서 갈라지지 않도록 한국어 줄바꿈 규칙을 보완하고 긴 장면 제목을 정리했습니다.
- 장면 이미지를 PC에서도 상단에 크게 배치하고, 설명은 이미지 아래의 별도 접이식 영역으로 분리했습니다. 화면 크기와 관계없이 먼저 장면 전체를 보고 원할 때 설명을 읽는 순서입니다.
- 선택지 왼쪽에 구별되는 보더를 두고 터치 영역을 키웠습니다. 헤더 아이콘도 버튼의 실제 상자 중앙에 정렬했습니다.
- 최종장 상태 표시에는 어두운 주황 계열을 사용해 위기 정보와 분홍·빨강 계열 선택 버튼이 한 덩어리로 보이지 않게 했습니다.
- 개발·기획 크레딧은 채용 담당자와 포트폴리오 독자도 빠르게 훑도록 `SYSTEM NOTES`로 구성했습니다. 프로젝트 역할, React/Vite, 서사 시스템, 판정·게임 상태, 반응형 UI, 접근성, 서체를 명시하고 `Lee YJ` 서명이 모바일에서 줄바꿈되지 않게 했습니다.

### 완주·도감 경험

- 엔딩 6개와 히든 후일담을 모두 확인한 뒤에는 완주 일러스트, 감사 문구, 아카이브 상태, 개발자 서명을 보여줍니다. 완주 그림은 WebP로 제공하며, 작은 화면에서도 잘리지 않도록 이미지 전체를 우선 노출합니다.
- 히든 후일담을 열 때 모달 스크롤을 맨 위로 초기화해 사용자가 직접 위로 올리지 않아도 첫 문장부터 읽을 수 있습니다.
- 엔딩 크레딧의 이름은 한 줄로 고정하고, 엔딩 종류와 어울리지 않는 문구는 빼서 생존 결과를 혼동시키지 않도록 했습니다.
- 6개 엔딩 수집 후 메인 화면에는 감사 창과 Canvas 폭죽 연출을 띄웁니다. 이펙트 끄기 설정과 모션 감소 환경을 존중합니다.

### 게임 피드백·사운드

- 조사 규칙, 판정 난이도 감소, HP/SAN 변화 등 진행과 생존에 영향을 주는 정보는 중립적인 본문과 색으로 구분했습니다. 중요한 규칙을 빠르게 훑어도 발견할 수 있게 하되, 버튼의 시각적 우선순위는 유지합니다.
- 도구 획득 문구가 모바일 상자 밖으로 넘치지 않게 하고, 조사 선택지는 한 화면에서 비교하기 좋은 2열 구성을 유지했습니다.
- Web Audio API로 생성하는 구역 전환음은 원래의 밝은 4음 팡파르를 낮고 무거운 2음으로 바꿨습니다. 사운드가 묻히거나 아예 들리지 않는 문제를 확인하며 음량과 음색을 조정해, 긴박한 상황에 맞는 짧은 피드백으로 정리했습니다.
- 플래시, 암전, 글리치 등 장면 연출은 효과 끄기 및 `prefers-reduced-motion` 경로를 함께 제공합니다.

### 게임 간 연결과 기술적 선택

- 두 게임 메인에 서로의 작품으로 이동하는 작은 인월드 배너를 배치했습니다. 별도 홍보 화면처럼 커지지 않게 해 분위기를 유지하면서 다른 작품의 존재는 알 수 있게 했습니다.
- 크레딧은 두 작품에서 같은 목적과 AI 사용 고지를 갖도록 맞췄습니다. Codex·GPT·Gemini를 개발에 활용했고 일부 이미지를 AI로 생성했음을 투명하게 밝힙니다.
- 엔딩 수집과 게임 회차 상태를 분리했습니다. 도감은 `localStorage`에 남기고, 재시작은 현재 회차만 초기화합니다. 홈 이동과 새 회차 시작 기능을 분리해 진행 중인 이야기를 실수로 잃지 않게 했습니다.
- 게임 규칙은 테스트 가능한 상태 전이와 스테이지 핸들러로 두고, React UI·데이터·사운드 합성을 분리했습니다. WebP를 사용해 장면의 시각 품질을 유지하며 다운로드 크기를 줄였습니다.
