# 00:37 AM — 심야 지하철 생존기

> 막차에 오른 직장인이 D20 판정과 제한된 조사 기회로 지하철의 이상 현상에서 탈출하는 React 텍스트 호러 TRPG입니다.

## 게임 소개

비가 내리는 자정 00시 37분, 신도림역 막차 6호차. 객실의 불이 꺼진 뒤 승객들이 사라지고, 당신은 지상으로 이어지는 길을 찾아야 합니다.

게임은 짧은 2장면 프롤로그로 시작합니다. 열차가 역으로 들어오는 화면 위에서 문장이 출력되며, 처음 본 뒤에는 같은 브라우저에서 프롤로그를 자동으로 생략합니다. 언제든 **인트로 건너뛰기**로 바로 캐릭터 생성으로 넘어갈 수 있습니다.

```text
프롤로그
  ↓
캐릭터 생성 · 컨디션 D20
  ↓
암전된 6호차 → 선로 터널 → 신도림 환승역 플랫폼 → 환승 상가
  ↓
환기탑 갱도 · 최종전
  ↓
엔딩 카드 · 엔딩 도감
```

## 플레이 방식

### 캐릭터와 컨디션

5개 아키타입 중 하나와 성별을 선택합니다. 사원증 미리보기에서 포트레이트, 능력치, 시작 소지품을 확인한 뒤 탑승을 확정합니다.

- 분석형 엔지니어
- 생존형 헬스인
- 칼퇴 지향 회피러
- 강철 멘탈 협상가
- 한탕주의 방관자

이후 D20으로 당일 컨디션을 정합니다. 능력치와 특성은 이후 STR / DEX / INT / WILL / LUK 판정에 영향을 줍니다.

```text
판정값 = D20 + 능력치 보정 + 특성 보정
```

Natural 20은 대성공, Natural 1은 대실패입니다.

### 조사 기회

Stage 1~4에는 단서가 있는 장소가 6곳씩 있습니다. **한 구역에서 조사할 수 있는 곳은 최대 3곳**입니다.

- 선택지 위 HUD에서 현재 위치와 `남은 조사 기회 n/3회`를 확인합니다.
- 조사 전에는 보상명이나 정답 행동 대신 현장 단서만 보입니다.
- 조사한 뒤에야 아이템, 위험, 판정 결과가 드러납니다.
- 헤더의 전구 버튼은 정답을 직접 말하지 않는 한 줄 생존 힌트를 표시합니다.

얻은 도구와 조사 기록은 이후 탈출 조건, 위험 회피, 최종전의 선택지에 연결됩니다.

### 최종전

환기탑에서는 **배기팬 → 추격자 → 맨홀**의 세 단계를 제한된 턴 안에 넘습니다. HP 또는 SAN이 0이 되면 탈출에 실패합니다.

## 주요 기능

### 장면·텍스트 연출

- 장면 이미지, 타이핑 텍스트, 조사 결과 모달
- 좁은 화면에서도 장면 이미지는 처음에 열어 두고, 상황 설명만 접힌 상태로 표시
- 이야기 모달은 바깥을 누르거나 `>다음`을 눌러 즉시 문장을 완성한 뒤 다음 진행
- 엔딩 진입 시 짧은 암전과 신호 노이즈 뒤에 카드와 후일담이 표시

### 아이템과 상태

- 도구, 단서, 회복 아이템을 인벤토리에 기록
- 스패너, 지렛대, 랜턴, 절연 장갑, 소화기 등은 실제 분기와 방어에 사용
- HP, SAN, 배터리, 조사 기록, 시나리오 플래그를 게임 엔진에서 관리
- 획득하지 않은 아이템은 텍스트 태그로도 안전하게 표시

### 엔딩 도감

BAD 3종, NORMAL, GOOD, TRUE의 6개 엔딩을 수집합니다.

- 첫 엔딩을 보기 전까지 도감은 잠김
- 완료한 카드만 브라우저의 `localStorage`에 저장
- 6개를 모두 모으면 히든 후일담 **04:44 AM — 폐쇄회로 밖의 기록** 해금
- 개발 환경의 메인 화면에서만 `Ctrl + Shift + F10`으로 도감 전체 해금 가능

엔딩 조건과 스포일러를 포함한 상세 검증 기준은 [QA 매뉴얼](docs/expansion-qa.md)에 정리했습니다.

### 반응형과 접근성

PC에서는 캐릭터 시트, 내러티브, 시스템 로그의 3열 구성을 사용합니다. 화면이 좁아지면 캐릭터 시트와 로그는 접을 수 있는 패널로 재배치되고, 선택지는 작은 화면 폭에서도 읽고 누를 수 있게 정돈됩니다.

설정은 브라우저에 자동 저장됩니다.

- 글씨 크기: 기본 / 크게
- 번쩍이는 이펙트 제거: 화면 반전, 점멸, 캔버스 효과, 엔딩 전환 생략
- 주사위 연출 생략: 다회차에서 회전 대기 없이 결과 즉시 표시

`prefers-reduced-motion`도 감지해 타이핑과 애니메이션을 줄입니다.

## 구조

```text
src/
├── components/
│   ├── console/       # 시스템 로그, 진행 추적
│   ├── layout/        # 헤더와 반응형 레이아웃
│   ├── modal/         # 주사위, 엔딩, 도감, 설정, 공통 대화상자
│   ├── narrative/     # 프롤로그, 장면, 조사, 선택지
│   └── sheet/         # 캐릭터 시트와 인벤토리
├── data/              # 아키타입, 아이템, 장면, 탐사, 엔딩 데이터
├── hooks/             # 게임 엔진, 설정, 사운드, 타이핑, 엔딩 수집
├── state/
│   ├── stages/        # 스테이지·탐사·최종전 핸들러
│   └── *.js           # reducer, 규칙, 인벤토리 상태
└── utils/             # D20, 이야기 흐름, 엔딩 저장값 처리

public/assets/
├── characters/        # 남녀 아키타입 포트레이트
├── scenes/            # 프롤로그, 스테이지, 이벤트 장면
├── cards/             # 엔딩 카드
└── items/             # 도구와 단서 WebP 에셋
```

화면 렌더링, 데이터, 상태 전이, 스테이지 규칙을 분리해 시나리오 변경이 UI 컴포넌트 전체로 번지지 않도록 구성했습니다.

## 실행

```bash
npm install
npm run dev
```

```bash
# 정적 검사
npm run lint

# 게임 규칙 테스트
npm test

# 프로덕션 빌드
npm run build
```

이미지 원본을 WebP로 최적화할 때는 다음 명령을 사용합니다.

```bash
npm run optimize:images
```

## 검증 범위

현재 18개의 게임 로직 테스트는 다음을 확인합니다.

- reducer 불변성 및 재시작 초기화
- D20 전체 눈금, 컨디션 경계값, 능력치 보정
- WebP 에셋 경로와 데이터베이스 연결
- 6개 조사 선택지, AP 차감, 중복 조사 방지
- 핵심 도구 분기와 BAD END 1 / 2 / 3
- 최종전 3단계, 0턴 방어, 마지막 턴 탈출
- 아이템 소모, 회복 상한, 장갑·CCTV 보호 효과
- TRUE / GOOD / NORMAL 경계와 손상된 엔딩 저장값 복구

브라우저 흐름 검증 스크립트는 `tools/`에 포함되어 있습니다.

## 핵심 목표

이 프로젝트는 상태가 많은 인터랙티브 콘텐츠를 React에서 어떻게 읽기 쉽게 구성하는지에 초점을 둡니다. 제한된 조사 기회, 누적 아이템과 플래그, D20 판정, 카드 수집을 하나의 진행 흐름으로 연결했습니다.
